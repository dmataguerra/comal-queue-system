\subsection{IPC and local browser events}

Desktop subscriptions broadcast estado, config, contenido, pantallas and entregaAudio through named IPC channels. The sandboxed preload exposes the limited TurneroApi; its inline channel literals are checked against shared/ipc-channels.ts.

Browser GET /api/inicial fetches current state; GET /api/events uses Server-Sent Events with JSON \{tipo, datos\}. Event types are estado, config, contenido, pantallas and entregaAudio. The browser test requests a free port, reads the origin from its own log and checks the diagnostic data directory, preventing accidental use of another running instance on 4317. This is SSE, not Socket.IO or WebSocket. Reconnection refreshes current state; it does not replay old announcements.

Announcement IDs increase during a session. Delivery statuses are validated by ID and number; terminal states cannot be reversed by late acknowledgements. The bounded in-memory delivery history retains up to 100 entries without evicting active ones. Multiple public windows can play the same announcement: there is no single-output election.

Evidence: public/browser-transport.js; main/servidor-web.ts; main/entregas-audio.ts
