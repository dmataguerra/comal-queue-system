\subsection{Trust and capability boundaries}

No user login or account roles exist. Desktop authorization is based on registered window, exact page URL and main frame, with runtime payload validation. Public desktop renderers cannot dispatch queue mutations or request full diagnostics; they have only the allowed playback, reading and reporting capabilities.

The HTTP server listens on 127.0.0.1. Every request requires the exact Host. POST additionally requires the exact local Origin, application/json and X-Turnero-Cliente: navegador. These are local request checks, not user authentication; any local client that supplies them can access the exposed API.

Do not describe the public browser UI as an authenticated security role. LAN administration, remote devices and public hosting are unsupported.

Evidence: main/seguridad-ipc.ts; main/servidor-web.ts
