\subsection{Persistence and legacy database migration}

The active product stores config.json, estado.json, turnero.log and editable contenido/ under the effective data directory, normally \%APPDATA\%/comal-local/datos in packaged 0.3.1. TURNERO\_DATOS overrides it for isolated tests; development defaults to the repository root.

estado.json contains fecha, actual, llamados, optional desde timestamps and guardadoEn. Undo history and announcement deliveries are session memory and do not survive restart. Only same-day, unexpired numbers return; old announcements never replay automatically.

SQLite is used only to read a supported 0.2.0 profile during migration. Up to six unique ready numbers last announced today are imported, with a fresh five-minute validity window; compatible messages and YouTube configuration are mapped. The legacy database remains untouched. The data/ SQLite files in the repository are legacy material, not active storage.

Evidence: main/persistencia.ts; main/carpeta-datos.ts; main/migracion-02.ts
