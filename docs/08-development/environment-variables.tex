\subsection{Environment variables}

\begin{longtable}{P{0.22\textwidth}P{0.13\textwidth}P{0.20\textwidth}P{0.35\textwidth}}
\toprule
Variable & Required & Component & Purpose/default \\
\midrule
\Code{HOST} & No & server & Listen address; defaults \Code{127.0.0.1}. Electron sets it to loopback. \\
\Code{PORT} & No & server/CORS & Listen port and allowed-origin port; defaults 3001. Must be integer 1--65535 in \Code{main.ts}. \\
\Code{DATABASE_PATH} & No & database & SQLite filename; defaults \Code{data/comal.sqlite}. May be \Code{:memory:} in direct construction/tests. Electron uses its user-data directory. \\
\Code{MUSIC_PATH} & No & media & Root catalog directory; defaults \Code{data/music}. Electron uses packaged extra resources. \\
\Code{ALLOWED_ORIGINS} & No & HTTP/WebSocket CORS & Comma-separated additional origin strings; default empty in addition to built-in local origins. Values are trimmed but otherwise not validated. \\
\Code{ELECTRON_RUN_AS_NODE} & Electron-managed & Electron child & Set to \Code{1} so Electron's executable runs the compiled Node server. \\
\bottomrule
\end{longtable}

No secret-valued environment variable is referenced. The repository ignores \Code{.env} but does not load it automatically; environment provisioning belongs to the shell/process supervisor. Do not commit real data paths or future secrets.

\textbf{Example for a LAN-bound standalone server (security review required):}
\begin{CodeBlock}
$env:HOST = '0.0.0.0'
$env:PORT = '3001'
$env:DATABASE_PATH = 'C:\comal-data\comal.sqlite'
$env:MUSIC_PATH = 'C:\comal-data\music'
npm start
\end{CodeBlock}

Exposing the current unauthenticated API to a network is not a production recommendation; it merely illustrates actual variable use.
