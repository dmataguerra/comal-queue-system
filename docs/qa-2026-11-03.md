| Finding | Impact and correction | Verification |
| --- | --- | --- |
| P1 — HTTP file-stream errors escaped request handling | `createReadStream().pipe(res)` had no stream error handler. A file disappearing or becoming unreadable during a browser media request could cause an uncaught exception in the main process. Both full-file and ranged transfers now use an awaited stream pipeline; failed responses close cleanly. | The injected read-failure regression failed with `uncaughtException` before the fix and passes afterward, including a subsequent healthy API request. See [before](../test-results/qa-2026-11-03/http-regression-before.log) and [after](../test-results/qa-2026-11-03/http-regression-after.log). |
| P1 — vulnerable dependency versions | The baseline audit reported **5 high and 29 moderate** findings. Compatible dependency updates remove every high finding and one moderate finding. Minimum Electron and Vite versions were raised in the manifest. | Final audit: **0 critical, 0 high, 28 moderate**. See [audit](../test-results/qa-2026-11-03/audit-final.log). |
| P2 — insufficient text contrast | Automated checks found small text below 4.5:1 in breadcrumbs, date/footer text, media guidance, the F1 hint and tour supporting text. A darker shared blue muted-text color and an opaque F1 hint correct these cases. | **22 automated accessibility evaluations passed** across desktop/browser, both themes, help, tours, diagnostics and the public display. [Final results](../test-results/accessibility-Ee50f5/resultado.json). This is automated coverage, not full WCAG certification. |
| Test reliability — reduced-motion timing | The standalone background test asserted the result after a fixed 200 ms, while hidden Chromium windows can defer media-query notifications. It now requests a compositor frame and waits for both the media preference and animation count to settle. | The original run failed `7 !== 0`; the corrected test passes and still checks animations off, on and off again. [Recheck](../test-results/qa-2026-11-03/background-after.log). |
| Coverage gap — installed help/manual | Source help tests did not prove the new help feature was present in the actual installer. | Installed smoke coverage now verifies the bundled PDF bytes, help/tour opening and closing, and blocking a prepared valid ticket during a tour. |
| Coverage gap — recurring validation | Destructive-input, display-scaling and standalone background tests were outside the regular Windows validation workflow. | CI now runs these checks and the new accessibility audit. The updated workflow has been reviewed locally; a hosted CI execution is not claimed. |

The remaining **28 moderate audit findings are in build/lint dependency chains**, rooted in the reported minimatch advisory and propagated through dependent packages. They remain unresolved and require dependency-maintainer-compatible updates or a separately documented risk decision. No forced major overrides, audit suppression, or reduction of the existing high-severity CI gate was applied. Electron is declared as a development dependency but ships as the application runtime; its update must not be dismissed based on a production-only npm audit.

The Electron certificate-validation mitigation is documented in the [maintainer advisory](https://github.com/electron/electron/security/advisories/GHSA-jr5w-w6x2-84p9). The remaining minimatch finding is described in its [maintainer advisory](https://github.com/isaacs/minimatch/security/advisories/GHSA-g3hv-75wg-m249); the local npm audit is the source for the dependency counts above.

## Remaining production acceptance

1. **390-minute endurance run:** deliberately omitted at the user's request; the shorter preflight was selected. Previous October evidence belongs to an earlier revision and does not certify this one.
2. **Real hardware:** PC, HDMI adapter/splitter, two-TV arrangement, display disconnect/reconnect, Windows display scaling and audible speaker/HDMI output need operational acceptance. Software audio acknowledgements do not prove sound was physically heard. The current app opens one public window on one selected secondary display; two TVs can mirror that output using suitable hardware.
3. **Signing and distribution:** this candidate is unsigned. Approved publisher identity, timestamped Setup/application/uninstaller signatures, standard-user acceptance and SmartScreen behavior remain release checks. Nothing was published, pushed or deployed.
4. **External services:** real YouTube playback and weather-service behavior were not certified. Creation/fallback paths were exercised; live external-service acceptance remains separate.
5. **Security/accessibility review:** resolve or explicitly assess the 28 moderate toolchain findings. Automated scans do not replace independent penetration testing, human accessibility/screen-reader review, or resource/license review.

No test campaign can prove absence of all defects. The evidence above supports a bounded local QA assessment, with the outstanding release conditions stated explicitly.
