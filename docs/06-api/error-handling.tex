\section{Error handling}

\subsection*{Backend}

Validation and domain failures use Nest exceptions:
\begin{itemize}
  \item \Code{BadRequestException} (400): malformed bodies, unknown fields, invalid ranges/identifiers/provider URLs, unavailable local playlist;
  \item \Code{NotFoundException} (404): unknown turn or unlisted/missing local file;
  \item \Code{ConflictException} (409): duplicate active number, incompatible request-ID reuse, or mutation/recall of a closed turn.
\end{itemize}

Nest's default exception serialization is relied upon; no repository-defined error code, envelope, localization contract, or global exception filter exists. Unexpected SQLite/filesystem/programming errors become framework 500 responses and server logs. Transactions roll back synchronous exceptions.

\subsection*{Frontend HTTP}

Requests abort after eight seconds. The client attempts JSON parsing and displays a returned string \Code{message}; otherwise it uses a generic local-connection message. There is no retry except user repetition, no offline mutation queue, and no differentiation among validation, conflict, timeout, and server failure beyond text.

\subsection*{Realtime}

Disconnect/connect-error sets a visible offline state. The last snapshot stays in memory, cashier mutations are disabled, the public display warns about staleness, and pending announcement audio is aborted. Reconnection replaces state. There is no durable missed-event recovery, but state itself is restored.

\subsection*{Multimedia}

YouTube load timeout, script failure, provider errors, embed restriction, autoplay block, and offline events produce fallback UI; some allow retry. Local audio element failure produces a notice. Queue state remains independent. Public audio activation failure is not currently surfaced because activation is never attempted there.

\subsection*{Inconsistencies}

Client and server YouTube validation differ; settings duration UI caps 20 while the server caps 30; no global React error boundary exists; MediaService startup filesystem failures can prevent server start. These are registered as technical debt.
