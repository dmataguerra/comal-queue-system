\section{Product documentation}
\subsection{Product vision}

\textbf{Confirmed product statement.} COMAL Queue is a local application for publishing ticket numbers after orders are ready for pickup. A cashier copies the number from an existing ticket, optionally assigns pickup counter 1 or 2, and the system immediately stores and broadcasts the ready turn. A public display shows the ready list and a time-limited visual callout.

The source and interface identify the operating context as the Troyanos/Comal++ cafeteria associated with the Facultad de Informática, Universidad Autónoma de Querétaro. The exact product name is inconsistent: repository/package text uses COMAL, Comal++, and \Code{comal-local}, while the latest interface is branded Troyanos. The commercial or institutional naming decision is \Unknown.

\textbf{Problem addressed.} The application bridges the period between preparation outside this system and customer pickup. It provides a shared, persistent view of which printed ticket numbers are ready and lets staff remove them after delivery or an erroneous capture.

\textbf{Operational boundary.} This is not a point-of-sale, preparation, kitchen, payment, inventory, or ticket-printing system. Its first implemented state is already \Code{ready}; all earlier order activity occurs elsewhere.

\textbf{Product principles evidenced by the repository:}
\begin{itemize}
  \item queue operation and bundled visual/audio resources are local;
  \item SQLite preserves operational state across process restarts;
  \item Socket.IO distributes changes to concurrent browser views;
  \item YouTube is optional and explicitly fails back to local visuals;
  \item repeated network submissions are made idempotent by caller-supplied request identifiers.
\end{itemize}
